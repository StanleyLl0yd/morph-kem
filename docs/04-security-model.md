# 04 — Security model

## Separation of claims

The project keeps four layers separate:

1. **combinatorial hardness** — properties of a mathematical search problem;
2. **distributional hardness** — hardness on instances actually generated by the experiment;
3. **primitive security** — one-wayness or indistinguishability of a trapdoor construction;
4. **KEM security** — IND-CPA / IND-CCA style security of a complete scheme.

No layer follows automatically from a lower layer.

## Equivalent-witness rule

A security experiment must define success by the **public mathematical relation**, not by recovery of the generator's private history.

If multiple witnesses satisfy the same public relation, every one of them is an attacker success.

The repository must never treat these as failures merely because they differ from the planted witness:

- a different reduction path;
- a different irreducible residual;
- a different acyclic Morse matching;
- a different spanning tree;
- a different preimage accepted by the relation.

M2/A-015 motivated this rule. M3 implements it explicitly.

## M3 relation experiment

M3 publishes a complex and a target critical vector.

A witness is accepted exactly when it is:

- a matching of codimension-one Hasse incidences;
- simplex-disjoint;
- acyclic after reversing matched Hasse arcs;
- equal to the declared critical vector.

No planted-core digest participates in the M3 success relation.

M3 is still broken: A-016 constructs equivalent witnesses directly on the generated graph-expanded family.

This is a distribution failure, not a reason to weaken equivalent-witness semantics.

## Future primitive target

Before attempting a KEM proof, a future primitive must define a precise average-case search or indistinguishability game over its generated distribution.

The adversary receives all public data and succeeds upon producing any accepted witness or otherwise computing whatever secret value the public relation is meant to protect.

Only after that game survives structural cryptanalysis should key indistinguishability be considered.

## Eventual KEM goal

If a primitive survives cryptanalysis, an eventual target could be an IND-CCA KEM with explicit invalid-ciphertext handling and domain-separated key derivation.

No such claim currently exists.

## Threat model

Assume an attacker knows the complete specification, all algorithms, all generator rules, all public transformations, arbitrary public instances, and all source code.

Security must not rely on secrecy of the design.

## Side channels

A mathematically sound primitive can still fail through timing, memory access, parser behavior, allocation behavior, or error oracles.

Reference research code currently optimizes for clarity. A candidate constant-time implementation, if ever justified, would be a separate engineering milestone.

## Falsification criterion

Any practical attack that satisfies the public relation materially below the intended work factor is sufficient to reject the relevant parameters or construction.

A structural polynomial-time construction of accepted witnesses is an immediate rejection regardless of parameter size.
