# 30 — T0 bounded Pachner equivalence search specification

## Status

T0 is the first executable candidate selected by the K2.4 frontier review.

It is a **reconfiguration-search calibration**, not a trapdoor primitive, KEM, one-way function, or post-quantum assumption.

The exact question is:

> Given two small combinatorial triangulations of the same 3-sphere that were generated by a bounded state-dependent Pachner path, how difficult is it to recover **any** path no longer than the public bound after quotienting out vertex labels?

## 1. Why T0 is worth testing

Pachner moves are a complete local move calculus for PL triangulations: two triangulations of the same PL manifold are connected through bistellar/Pachner moves.

Useful references:
- Regina overview of Pachner moves: https://regina-normal.github.io/engine-docs/pachner.html
- Regina's exhaustive Pachner-graph search: https://regina-normal.github.io/docs/tri-modification.html

There is also concrete recent complexity evidence. Tillmann and Tsvietkova (2026) prove NP-hardness for a bounded move problem between 3-sphere triangulations involving bistellar moves and sparse degree-two edge collapses, and state that this yields the first NP-hardness result concerning moves between triangulations of a 3-manifold:

https://arxiv.org/abs/2606.14413

This is **worst-case evidence only**. T0 is designed to determine whether the project's generated positive instances are trivial long before any cryptographic interpretation.

## 2. Toy representation

T0 deliberately starts with **finite abstract simplicial complexes** rather than Regina's more general face-pairing triangulations.

A state is a pure 3-dimensional `SimplicialComplex` whose facets are tetrahedra.

The initial state is derived from the boundary of a 4-simplex, which is a triangulation of `S^3`.

Generation is allowed to use topology-preserving Pachner moves only. Therefore every generated state stays in the same PL 3-sphere class without invoking a general 3-sphere recognition algorithm.

### Closed-manifold diagnostics

Every generated/challenge state must satisfy at least:
- every facet has four vertices;
- every triangular face occurs in exactly two tetrahedra;
- every vertex is used;
- the 1-skeleton is connected;
- Euler characteristic is zero.

These checks are diagnostics, not substitutes for a full manifold-recognition theorem. Topology preservation comes from legal move replay from the known seed state.

## 3. Label quotient

Vertex names must not carry the planted route.

Two states are considered equal when their abstract simplicial complexes are isomorphic.

T0 therefore requires an exact toy canonical signature:

~~~text
Canon(K) = lexicographically minimal canonical tetrahedron list
           over all vertex relabelings consistent with a refinement partition
~~~

For the tiny baseline, exact search is acceptable. Partition refinement should first split vertices using public incidence signatures such as:
- tetrahedron degree;
- edge-degree multiset;
- link f-vector;
- refined neighbor colors.

Permutations are enumerated only inside unresolved color classes.

The test suite must verify:
- invariance under arbitrary relabeling;
- equality iff tested isomorphic toy states receive the same signature;
- no use of generation history.

## 4. Challenge move set

The first challenge uses only the **2-3** and **3-2** Pachner moves.

This is deliberate. A 1-4 move introduces a new degree-four vertex whose immediate 4-1 inverse may leave a conspicuous planted trail. Regina likewise uses 2-3/3-2 moves for its exhaustive 3-manifold Pachner-graph search.

Source:
https://regina-normal.github.io/docs/tri-modification.html

### 2-3 move

Let two tetrahedra share exactly the triangle `(a,b,c)` and have distinct opposite vertices `d,e`.

The move is legal when the belt edge `(d,e)` is absent.

Replace:

~~~text
abcd, abce
~~~

by:

~~~text
abde, acde, bcde.
~~~

### 3-2 move

Let edge `(d,e)` have degree three, with incident tetrahedra:

~~~text
abde, acde, bcde
~~~

for three distinct opposite vertices `a,b,c`.

The move is legal when the belt face `(a,b,c)` is absent.

Replace the three tetrahedra by:

~~~text
abcd, abce.
~~~

Each implementation must verify that applying a move and its exact inverse returns an isomorphic canonical state.

## 5. Burn-in

The boundary of the 4-simplex is too symmetric and has a complete 1-skeleton, so no 2-3 move is initially available.

T0 generation therefore has a separate **burn-in** phase that is not part of the challenge witness.

Burn-in may use a small deterministic number of legal 1-4 and 2-3/3-2 moves to produce a richer public starting triangulation `R0` with:
- fixed small vertex count, initially target 7–9;
- at least two legal challenge moves;
- no degree-four vertex whose 4-1 removal is part of the challenge move set;
- no challenge-history leakage because only the final canonical `R0` is published.

The challenge itself then stays in the fixed-vertex 2-3/3-2 subgraph.

## 6. Challenge generation

For parameter set `t0-L`:

1. deterministically generate and canonicalize burn-in start state `R0`;
2. set current state `R <- R0`;
3. for `i=1..L`, enumerate legal 2-3/3-2 moves;
4. reject candidate moves whose result is isomorphic to the immediately previous state;
5. reject candidate moves that revisit any earlier canonical state in the planted path;
6. require a configurable minimum public branching factor before choosing a step;
7. choose a candidate using domain-separated deterministic randomness;
8. canonicalize the final endpoint `R1`;
9. publish `(R0,R1,L,parameter-id)`;
10. keep the planted path only as reference evidence.

The public bound is initially exactly the planted length `L`.

If an attacker finds a shorter path, that is a successful and especially important negative result.

## 7. Exact witness relation

A witness is a sequence of legal move descriptors:

~~~text
W = (m1,...,mt), t <= L.
~~~

Verification:

1. start from the public `R0`;
2. verify and apply each move to the current state;
3. after the last move compare `Canon(R)` with `Canon(R1)`;
4. accept iff equal and `t <= L`.

The verifier does not compare with the planted path.

## 8. T0-A01 — exhaustive breadth-first search

For the smallest path lengths, enumerate the canonical reconfiguration graph from `R0` up to depth `L`.

Record:
- canonical states visited;
- edges explored;
- branching distribution;
- first target depth;
- number of shortest target predecessors;
- state collisions / multiple paths reaching the same state.

If BFS routinely reaches the endpoint at depth far below `L`, the generator is rejected.

## 9. T0-A02 / A-023 — bidirectional BFS

Search simultaneously from `R0` and `R1` because 2-3 and 3-2 are mutual inverses.

Canonical state signatures are the join keys.

This is the direct successor to the M1 meet-in-the-middle lesson, but unlike M1:
- each state's move set is different;
- branching is not fixed at two;
- paths merge;
- the move descriptors depend on current combinatorics.

These differences must be **measured**, not assumed beneficial.

Metrics:
- forward/reverse states;
- frontier sizes by depth;
- first intersection depth;
- recovered path length;
- memory;
- duplicate-state ratio.

## 10. T0-A03 — informed search

Implement at least simple public lower-bound / ordering heuristics:
- absolute tetrahedron-count difference;
- edge-degree histogram distance;
- vertex-link signature distance;
- number of immediately legal inverse/simplifying moves;
- canonical incidence fingerprint distance as an ordering heuristic only.

Run A* or IDA* only where the chosen heuristic is admissible; otherwise label it beam/greedy search rather than A*.

No heuristic quality claim may be inferred from a few instances.

## 11. T0-A04 — random-restart and greedy simplification

Pachner graphs often contain huge numbers of equivalent paths.

Run deterministic-seeded random walks and greedy policies that favor:
- smaller tetrahedron count;
- higher overlap of coarse public invariants with `R1`;
- moves not recently reversed;
- unexplored canonical states.

Equivalent path multiplicity is itself attack surface.

## 12. T0-A05 — bounded planning / SAT gate

Before increasing `L`, encode bounded path existence as a solver problem or integrate a mature planning/constraint backend.

The exact encoding may be deferred until the explicit move universe is stable, but parameter growth is forbidden until the solver gate exists.

At minimum compare with the lesson from H2.1: failure of hand-written Python backtracking is not evidence of hardness if an industrial solver can recover a witness.

## 13. T0 baseline parameter ladder

Provisional toy sets:

~~~text
t0-4: planted challenge length 4
t0-6: planted challenge length 6
t0-8: planted challenge length 8
~~~

All are experiment sizes only.

Burn-in parameters are fixed and encoded in the parameter record so generation remains byte-deterministic.

## 14. Mandatory rejection conditions

Reject the T0 generator if any of the following appears across deterministic samples:
- endpoint routinely reachable in much less than `L`;
- reverse move trail is locally recognizable;
- bidirectional search visits only a tiny number of states;
- canonicalization exposes a near-deterministic route;
- one coarse invariant orders moves almost perfectly;
- huge witness multiplicity makes any path easy to find;
- challenge paths decompose into independent local regions;
- a bounded solver recovers all toy instances cheaply.

Increasing `L` after a structural failure is not an acceptable repair.

## 15. What success would mean

Even if T0 resists the implemented toy attacks, the conclusion would be only:

> this generated reconfiguration distribution deserves deeper study.

It would **not** imply:
- average-case hardness;
- post-quantum hardness;
- existence of a trapdoor;
- existence of public-key encryption;
- KEM security.

A separate T1 milestone would then need to construct and attack a trapdoor distribution where secret structural information accelerates recovery for fresh public-evaluation outputs without being equivalent to public canonicalization.

## 16. Security status

No one-wayness, average-case hardness, post-quantum security, IND-CPA, IND-CCA, KEM, or production-security claim exists.
